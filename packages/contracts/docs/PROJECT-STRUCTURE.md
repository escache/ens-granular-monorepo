# Project Structure

This document describes the semantic organization of files and directories in the contracts package.

## Directory Structure

```
packages/contracts/
├── src/                          # Source contracts
│   ├── interfaces/               # Contract interfaces
│   ├── examples/                 # Example implementations
│   ├── test/                     # Testable contracts and mocks
│   │   └── mocks/               # Mock contracts for testing
│   └── scripts/                  # Source-level scripts
├── test/                         # Test files
│   └── mocks/                   # Test-specific mocks
├── scripts/                      # Deployment and utility scripts
│   └── deployment/              # Deployment scripts
├── config/                       # Configuration files
│   └── networks/                # Network-specific configurations
├── docs/                         # Documentation
├── reports/                      # Generated reports and results
│   └── test-results/            # Test execution results
├── artifacts/                    # Compiled contract artifacts (generated)
├── cache/                        # Hardhat cache (generated)
└── node_modules/                 # Dependencies (generated)
```

## Directory Descriptions

### `/src`
**Purpose**: Contains all source Solidity contracts and related code.

- `interfaces/` - Contract interface definitions (e.g., `IENSRegistry.sol`, `IGranularAssignmentController.sol`)
- `examples/` - Example contract implementations and reference code
- `test/` - Testable contract variants and mock implementations
  - `mocks/` - Mock contracts for testing (e.g., `MockENSRegistry.sol`)
- Core contracts - Main production contracts (e.g., `ENSNamingDelegateGranular.sol`, `GranularResolver.sol`)

### `/test`
**Purpose**: Test files and test-specific assets.

- Test files - Mocha/Chai test suites (e.g., `FullControllerAutomated.test.js`)
- `mocks/` - Additional mock contracts used only in tests

### `/scripts`
**Purpose**: Deployment and utility scripts.

- `deployment/` - Scripts for deploying contracts to various networks
  - `deploy-gna.js` - Deploy Granular Name Assignment contracts

### `/config`
**Purpose**: Configuration files and settings.

- `networks/` - Network-specific configurations
  - `addresses.js` - Contract addresses for different networks

### `/docs`
**Purpose**: Documentation files.

- `FORK-TESTING.md` - Guide for testing with mainnet forks
- `ENS-COMPATIBILITY.md` - ENS ecosystem compatibility documentation
- `PROJECT-STRUCTURE.md` - This file

### `/reports`
**Purpose**: Generated reports, test results, and analysis output.

- `test-results/` - Test execution results and summaries
  - `test-results-full.txt` - Full test output
  - `test-results.json` - Test results in JSON format
  - `TEST-RESULTS-SUMMARY.md` - Human-readable test summary
  - `test-run-date.txt` - Timestamp of last test run

### `/artifacts`
**Purpose**: Compiled contract artifacts (auto-generated by Hardhat).

**Note**: Do not commit this directory to version control.

### `/cache`
**Purpose**: Hardhat compilation cache (auto-generated).

**Note**: Do not commit this directory to version control.

## File Naming Conventions

### Contracts
- **PascalCase**: `ENSNamingDelegateGranular.sol`
- **Interface prefix**: `I` prefix for interfaces (e.g., `IENSRegistry.sol`)
- **Mock prefix**: `Mock` prefix for mock contracts (e.g., `MockENSRegistry.sol`)
- **Testable prefix**: `Testable` prefix for testable variants (e.g., `TestableGranularResolver.sol`)

### Test Files
- **PascalCase.test.js**: `FullControllerAutomated.test.js`
- Descriptive names indicating what is being tested

### Scripts
- **kebab-case.js**: `deploy-gna.js`
- Descriptive action verb names

### Documentation
- **UPPERCASE-KEBAB-CASE.md**: `FORK-TESTING.md`
- **PascalCase.md**: For detailed guides

### Reports
- **kebab-case**: `test-results-full.txt`
- **UPPERCASE-KEBAB-CASE**: For summary documents

## Import Paths

When importing contracts, use relative paths from the `src/` directory:

```solidity
import "./interfaces/IENSRegistry.sol";
import "../interfaces/IGranularAssignmentController.sol";
```

When importing in tests, reference from the `src/` directory:

```javascript
const ENSRegistry = await ethers.getContractFactory("MockENSRegistry");
```

## Adding New Files

When adding new files, follow these guidelines:

1. **New Contracts**: Place in `/src` with appropriate subdirectory if needed
2. **New Interfaces**: Place in `/src/interfaces`
3. **New Tests**: Place in `/test` with descriptive name
4. **New Scripts**: Place in `/scripts/deployment` or appropriate subdirectory
5. **New Documentation**: Place in `/docs`
6. **Test Results**: Will be automatically generated in `/reports/test-results`

## Version Control

**Do NOT commit:**
- `/artifacts` - Compiled contracts
- `/cache` - Build cache
- `/node_modules` - Dependencies
- `/reports` - Generated reports (optional, can commit summaries)

**DO commit:**
- All source code in `/src`
- All test files in `/test`
- All scripts in `/scripts`
- Configuration files
- Documentation in `/docs`
- `package.json`, `hardhat.config.js`, etc.
